# UX and consistency audit — 2026-11-02

Scope: the whole public surface on `main` at `1f22bd26a` (378 public functions,
731 snapshot entries), from two points of view: a spatial neuroscientist using
the package for the first time, and an LLM coding assistant writing code
against it.

Method:

- A script scan of every public signature for naming and default
  consistency.
- Five probes that ran real code on simulator data: result objects, errors
  and warnings, onboarding docs, static plots, and a blind "LLM guesses the
  API" experiment.
- Every finding marked **R** was reproduced in the main session. **A** means
  an agent ran it and quoted the output. **C** means it was read in code only.

The ux-review workflow was not used. Its built-in project context is out of
date.

## 1. Silent wrong results (fix first)

Each of these runs to completion, warns about nothing, and returns a
plausible but wrong number. Each one breaks the project rule that the
obvious path must keep the meaning of the analysis.

| # | What the user does | What happens | Ev. |
| --- | --- | --- | --- |
| S1 | Passes positions in pixels (×8) to a cm environment | 7.3 s of a 120 s session is kept and 66/76 spikes are dropped. The rate map is built from that fragment. Out-of-environment and NaN samples are removed by interval gating; the warning returns early when any interval survives (`_intervals.py` ~1748). Only `result.n_spikes_outside_intervals` records it. | R |
| S2 | Filters by speed the numpy way: `times[speed>5], positions[speed>5]` | Gaps shorter than `max_gap=1.0` are bridged, so occupancy is 265.6 s instead of 232.1 s (`min_speed=5`). Spikes fired at rest are kept. | R |
| S3 | `compute_directional_rate(..., bin_size=6)`, reading the docstring's "6°" | One bin and MVL = 1.0, which looks like a perfect HD cell. `bandwidth=10` gives MVL = 0.0. Headings in degrees *are* caught; bin_size and bandwidth in degrees are not. | R |
| S4 | `decode_position(env, counts, np.nan_to_num(rates.firing_rates), dt=)` | 71% of posterior mass falls on bins with no rate estimate. The median error is 69.9 cm versus 43.0 cm with the result object. The NaN array warns well; the zero-filled array does not. | A |
| S5 | `decode_position(..., dt=25)` (ms) or `bin_spikes_in_time(dt=25)` | Runs. The posterior is about 120× overconfident. `dt` is never compared with `times`. | A |
| S6 | Spikes partly outside the recording (clock offset) | 28% of spikes are dropped with no warning. `_DROP_WARN_THRESHOLD = 0.5` (`encoding/_spatial_counts.py:68`). | A |
| S7 | `spatial_information(occupancy, rate)` with the arguments swapped | Returns 0.27–0.56 bits. Both arguments are positional and have the same shape. | A |
| S8 | `detect_laps` on a linear (non-loop) track | 15 "laps" with `direction='unknown'`. `detect_trials` is the right tool. | A |
| S9 | `bandwidth=0.05` (metres) on a cm environment | Runs with no smoothing and no warning. | A |

Suggested rule, to replace nine separate patches: **the public boundary warns
whenever more than a small fraction of the input is discarded or the input
contradicts a declared unit.** S1, S2, S6 and S9 are all "you lost or
mis-scaled data and we know it."

- S2 can be detected: masked time arrays have steps at whole multiples of the
  median dt.
- S3: refuse `bin_size > π/2` (rad) and warn when `bandwidth > 1` rad, both
  suggesting `angle_unit="deg"`.
- S4: warn when some bins are exactly 0 for every neuron and no `prior` is
  given.
- S7: make `occupancy` keyword-only.

## 3. API consistency (signature scan, R)

The contract in `.claude/rules/public-api.md` and
`tests/test_argument_conventions.py` covers argument order and banned names.
None of the following is enforced.

| Concept | Spellings in the public API | Suggest |
| --- | --- | --- |
| Random seed | `seed=` ×13 (all of `simulation`, `estimate_colormap_range_from_subset`), `rng=` ×58, `line_seed=0` (`detect_trajectory_radon`) | `rng=` everywhere |
| A region argument | `region`, `region_name`, `regions`, `goal_region`, `decision_region`, `goal_regions`, `goals`, and `goal=` (#256) | one rule, e.g. `region=` for one, `regions=` for several, role prefix only when two roles coexist |
| Time-bin width | `dt=` (decoding, `align_continuous_to_events`, `bin_spikes_in_time`) vs `bin_size=` (PSTH) | pick one for time bins |
| Same pre-entry window | `window_duration=` (VTE, pre-decision) vs `pre_window=` (`compute_decision_analysis`) | one name |
| Paired inputs | `_1/_2` (`field_stability`, `compute_field_emd`), `_a/_b` (`compare_spatial_rates`, `trajectory_similarity`), `_i/_j` (`field_overlap`), `angles1/angles2` | one suffix style |
| Unit selection | `unit_ids=` ×23 vs `cells=` (`null_events`, `spike_words`) | `unit_ids=` |
| Smoothing width | `smooth_window` vs `smoothing_window` (`generate_inhomogeneous_poisson_surrogates`) | one |
| `alpha` | significance level ×7 vs VTE mixing weight (`compute_vte_index`, `compute_vte_session`) | rename the VTE weight |
| `ax` | positional (methods, `plot_head_direction_tuning`, `plot_phase_precession`, `plot_circular_basis_tuning`) vs keyword-only (`plot_peri_event_histogram`, `plot_regions`), last (`plot_population_coverage`), `axes=` (`plot_peri_event_response`) | keyword-only `ax=` |
| Source/target | `resample_field(field, src_env, dst_env)` vs `map_probabilities(source_env, target_env, source_probs)` | same order and names |
| Graph input in `ops` | `G` (`distance_field`, `neighbors_within`, …), `graph` (`compute_diffusion_kernels`), `env` elsewhere | `graph` or accept `env` |
| Time argument | `in_epochs(t, …)` vs `times` everywhere else | `times` |

Defaults that differ for the same concept:

- `criterion`: required on `is_place_cell` but `"threshold"` on the other four
  `is_*_cell` predicates. The docstring says this is deliberate; either all
  five should require it or none should.
- `n_shuffles`: 1000 (×23), 300 (`pairwise_order_significance`), 200
  (`has_phase_precession` vs 1000 on `compute_phase_precession`), 100
  (`bias_similarity_significance`).
- `min_speed`: required ×7, `None` ×16, `0.0` ×2.
- `min_occupancy`: `None` on spatial rate and decode functions, `0.0` on
  every other encoding function.
- `metric` defaults to `geodesic` ×18 and `euclidean` ×13. The split looks
  principled (path length vs goal distance), but no docs page states the rule.

The return type should not depend on arguments:

- `compute_path_efficiency` returns `PathEfficiencyResult | pd.DataFrame`
  depending on `intervals` (R).
- `regions_containing_points(return_dataframe=)` and
  `simulate_trajectory_laps(return_metadata=)` change their return type
  through a flag.

## 4. Result objects (A unless marked)

- **Population `plot()` behaves three ways.**
  - `SpatialRatesResult.plot()` raises an actionable error.
  - `DirectionalRatesResult.plot` and `TuningCurvesResult.plot` take a
    required positional `idx` and fail with a bare `TypeError`
    (`directional.py:1827`, `tuning.py:677`) (R).
  - `PopulationPeriEventResult.plot()` draws a population mean titled like a
    single unit.
- **`PlaceFieldsResult`** does not follow the contract:
  - `to_dataframe` has no `unit_id` and no attrs.
  - There is no `summary_table`, `plot` or `peak_location`.
  - `detect_place_fields(env, rate_result, ...)` fails. `bandwidth` is
    required even though the rate result records it.
- **`place_cell_significance`** returns `dict[int, ShuffleTestResult]`, and
  `ShuffleTestResult` does not name the statistic or its unit. Its sibling
  `spatial_cell_type_significance` returns a full result with a table.
- **VTE** classifies trials with zero head-sweep variance as VTE on speed
  alone (6 of 40 T-maze trials, `behavior/vte.py:1520`).
- **`Lap.direction`** is clockwise/counter-clockwise only. On a linear track
  every lap is `"unknown"`.
- **Repr shows fields that are not attributes.**
  - `CellTypeSignificanceResult` repr shows `n_place=0`, but `.n_place`
    raises.
  - `mean_vector_length=0.61` in the `DirectionalRateResult` repr is a
    method, so `r.mean_vector_length > 0.2` raises `TypeError`.
  - A cheap scalar is sometimes a property and sometimes a method, with no
    rule.
- **Units are missing from metadata.**
  - `DecodingResult.to_dataframe().attrs == {}`, and the PSTH and trials
    frames have no units.
  - `Environment` repr shows no units or bin size.
  - xarray `units` is a string while DataFrame `units` is a per-column dict
    ("radians" vs "rad").
- **Single-unit `unit_id`** is `pd.NA` on rate results and `None` on
  `PeriEventResult`.
- **Directional results** give `peak_location()` = 2.775 rad but
  `preferred_direction` = 2.053 rad without explaining the difference.

## 5. Plotting (A, PNGs in the session scratchpad)

- `plot_population_coverage(show_field_count=True)` draws unvisited bins as 0
  (`encoding/population.py:601,634`, no `is_observed` mask) (R). This breaks
  "missing is not zero".
- `DecodingResult.plot` and `DirectionalPlaceFields.plot` put a bin index on
  a spatial axis. On 2-D arenas the result is a staircase of flattened bins.
  Use cm on 1-D tracks, and per-direction `plot_field` panels or marginals on
  2-D arenas.
- Polar plots on an ordinary `plt.subplots()` axis:
  - `plot_head_direction_tuning` raises a raw `AttributeError`.
  - `DirectionalRateResult.plot` silently draws an unlabelled Cartesian plot.
  - Check `ax.name == "polar"` and say how to make a polar axis.
- Functions overwrite the user's titles: `env.plot` sets "RegularGrid (2D
  Grid)", and the PSTH plot replaces the title you set. Set a title only when
  the function made the axes, or when `title=` is passed.
- Colorbars:
  - Missing labels on the object-vector, boundary-vector, view and
    egocentric plots.
  - `plot_field` defaults to `colorbar_label=""`.
  - `DecodingResult.plot` defaults to `colorbar=False`; elsewhere the default
    is `True`.
  - The flag is spelled `colorbar` or `add_colorbar`.
- `plot_regions`:
  - The aspect is not equal, so circles become ellipses.
  - Every region gets the same colour.
  - The legend is clipped.
- `plot_basis_functions` and `plot_session_summary` return a Figure and cannot
  draw into your own axes.
- Done well:
  - viridis everywhere, no jet.
  - No `plt.show()` calls.
  - NaN is clearly distinct from 0 on rate maps.
  - Polar plots follow the allocentric convention.

## 6. Errors (non-silent)

House style (`What / Why: / Fix:`, keyword-typo hints, unit heuristics,
the trajectory validator) is strong. A normal golden path emits **zero
warnings**. Gaps:

- **Wrong-kind input gives raw numpy errors.**
  - A list of trains passed to a single-unit function (`compute_spatial_rate`,
    `is_place_cell`, `decode_position`) raises "inhomogeneous shape after 1
    dimensions".
  - A result object passed where an array is expected raises "must be 2-D,
    got shape ()".
  - Detect these at the boundary and name the right call
    (`compute_spatial_rates`, `r.spatial_information()`).
    `BayesianDecoder.from_rates` already does this well.
- **`BayesianDecoder.fit(count_matrix)`** gets a "MATLAB zero padding"
  message. Its suggested fix turns counts into fake spike times.
- **Typo errors name the wrong function.**
  - A typo passed to `open_field_session`/`simulate_session` is reported
    against `simulate_trajectory_ou()`, which the user never called (R).
  - `decode_session(bandwdth=)` lists the extra kwargs but not "did you mean
    bandwidth" (R).
  - Invalid `method=` gives no close-match suggestion.
- **Times in ms, or a `pd.DatetimeIndex`,** warn well but still return an
  all-NaN map. Raise when every interval is excluded.
- **Style drift:**
  - 80 sites use `WHY:` instead of `Why:`.
  - E1006 repeats its fix.
  - `r.is_place_cell()` requires `criterion=`, whose only allowed value is
    `"threshold"`.
- **Exception types.** `except NeurospatialError` catches almost nothing a
  user hits: trajectory, neuron-count and `unit_ids` errors are plain
  `ValueError`. The claim in `docs/errors.md` overstates it.
- An AST heuristic flags 930 of 2370 raise sites with no remedy wording,
  private code included (C). Agent list:
  `scratchpad/errors/weak2.txt`.

## 7. Discoverability and docs (A)

- **Which decoder to start with.**
  - The root namespace exports `decode_position` (counts in), which its own
    docstring calls the "Main entry point".
  - `decoding.__doc__` and the README say to start with `decode_session`.
  - Export `decode_session` at the root.
- **`encoding` (86 names) and `behavior` (77)** have no "Start here" block.
  Their docstrings list only private submodules, while `decoding`'s Start Here
  is the model to copy. Add a question → function table for place cells:
  `compute_spatial_rate`, `has_place_field`, `detect_place_fields`,
  `is_place_cell`, `place_cell_significance`,
  `spatial_cell_type_significance`, `count_place_cells`, `.classify()`, and
  `.label_cell_types()`.
- **`neurospatial.io.nwb`** is missing from `dir(neurospatial.io)`, and
  `dir(neurospatial.io.nwb)` hides its lazy exports. Add `__dir__` returning
  `__all__`.
- **The README and the top-level docstring teach private import paths:**
  `simulation.models`, `simulation.trajectory`, `behavior.segmentation`,
  `ops.egocentric`, and others.
- **50 objects have two public paths**, nearly all of them `replay.X` and
  `replay.{calibration,dataset,methods,pairwise_order,arms}.X` (R). Pick one
  public home.
- **Terminology.**
  - "Place field" means the whole rate map in the quickstart and README, but
    a thresholded subset in the glossary and in `detect_place_fields`.
  - The glossary files the PSTH under "spike-triggered".
  - The glossary has no entries for epoch, interval, trial, lap, `max_gap`,
    `spike_window`, posterior or PSTH.
- **26 of 26** sampled docstring Examples ran. Several defaults have no stated
  reason:
  - `segment_by_velocity` (`min_duration`, `hysteresis`)
  - the 25 ms decode/PSTH bins
  - `detect_laps(min_overlap=0.8)`
  - the 5 cm `bandwidth`

## 8. LLM-specific confusion

Blind-guess experiment (A): ten common tasks were written from priors, then
fixed using only `help`/`dir`/errors. All ten were solved without reading the
source. The top-level `neurospatial.__doc__` was the most useful single aid.
**Caveat: these findings are a lower bound.** The agent already had the
project CLAUDE.md in context, which names `BayesianDecoder.from_rates`,
`decode_position`, `has_place_field` and the argument order. An assistant
working in a user's analysis repo would not see it. A clean rerun needs a
fresh session started outside this repo.

What tripped it:

- **Names it expected:**
  - `compute_place_field` → `compute_spatial_rate`
  - `compute_psth` → `peri_event_histogram`
  - `head_direction_tuning_curve` → `compute_directional_rate`
  - `n_bins=` → `bin_size=`
  - `smoothing_sigma` → `bandwidth`
  - `stats.shuffle_test` → `is_place_cell(criterion="shuffle")`
  - `BayesianDecoder(bin_size=)` → `dt=`
  - `env.save` / `Environment.load` → `to_file` / `from_file`; `env.save`
    raises a bare `AttributeError`

  Cheap fix: a small alias table in `Environment.__getattr__` and in the
  package/subpackage `__getattr__` that raises with a pointer, so a guess gets
  redirected instead of failing with no hint.
- **Signatures hide real defaults.**
  - `None` sentinels resolve to concrete values inside the function:
    `min_info=None` → 0.5 bits/spike, `alpha=None` → 0.05,
    `bandwidth=None` → a bin-size-dependent value (6.25 at 2.5 cm bins but
    5.0 when `units="cm"`).
  - An LLM reading `inspect.signature` sees `None`.
  - Raw float literals appear in signatures: `direction_bin_size=0.5235987755982988`
    (π/6), `slope_bounds=(-6.28…, 6.28…)`, `trial_probability=0.0416…`.
  - Either use real defaults or put the resolved value as the first sentence
    of the parameter doc.
- **Inconsistent verb prefixes reduce guessability.**
  - 42 public names start with `compute_`.
  - Their siblings do not: `spatial_information`, `border_score`,
    `angular_efficiency`, `traveled_path_length`, `goal_bias`,
    `mean_square_displacement`.
  - An LLM cannot infer which form exists. Choose and document the rule
    (e.g. `compute_*` = raw data in, result object out; bare noun = metric on
    an existing map), then apply it.
- **Methods vs properties** (section 4) and repr fields that are not
  attributes cause `TypeError`/`AttributeError` from code that reads
  naturally.
- **Section 1 matters most for LLMs:** an assistant will happily write
  `times[speed > 5]`, `nan_to_num(rates)` or `bin_size=6` and report the
  result. Warnings at the boundary are what an agent reads.
- **Missing `llms.txt` or agent quickref.** There is no user-facing (not
  contributor) machine-readable index. A generated `llms.txt` would give an
  assistant the map it otherwise reconstructs from `dir()`: public paths,
  one-line summaries, the argument-order table, and the units/missing-data
  conventions from CLAUDE.md. Generate it from `tests/data/public_api.txt`.

## 9. Keep

- The `What / Why: / Fix:` error format.
- The trajectory validator, with its index, recipes and swapped-argument
  detection.
- Keyword-typo hints.
- Unit heuristics with numbers (ms times, degree headings, sample indices
  given as spike times).
- `summary_table().attrs` recording units, thresholds and
  `unavailable_metrics` with reasons.
- `<NA>` rather than False for verdicts that cannot be computed.
- NaN kept distinct from zero in rate maps and plots.
- One-line reprs and `_repr_html_`.
- `[i]` / `sel(unit_id=)` setting the child's `unit_id`.
- A golden path with zero warnings.
- The decoding "Start Here" docstring.
- Consistent `(env, spike_times, times, positions)` order.
