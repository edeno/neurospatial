# Migrating to v0.6 and later

v0.6 made the result-object surface consistent across every encoding and
decoding domain (the "naming contract"). The unreleased changes after v0.6
remove the transition aliases and change how recordings with gaps, time windows
and argument order are handled. None of these changes has a compatibility shim,
so you must update call sites. Each section below gives the old call and its
current replacement; the [changelog](../changelog.md) lists every change.

## Affine environment geometry

`env.apply_transform(...)` retains bin IDs, neighbor order and exact supported
cells. Rotated, reflected and sheared Cartesian 2-D/3-D grids now retain linear
interpolation and movement allocation in their original grid axes. Their 2-D
field plots use `QuadMesh`, so scatter-only keyword arguments such as `s=` no longer
apply. Napari raster helpers refuse a framed grid; Matplotlib/video/HTML/widget
render its actual corners. Raster FFT/grid metrics keep their existing
world-aligned restriction.

Numerical operations require certified physical faces. Unequal scaling along
orthogonal retained grid axes can now pass that check; a shear generally
refuses smoothing, diffusion, gradients and divergence while retaining exact
geometry. Legacy records without normals keep their previous guaranteed
transforms. Saving uses nested binning codec version 3; current readers accept
versions 1 and 2, but older readers reject the new nested version.

See the [alignment workflow and capability table](../user-guide/alignment.md#transforming-environments)
for position-only and image-mask inputs, unit/frame metadata and clipping/rebin
behavior. A mask or tracking-derived domain does not assert physical walls.

## Track containment and nearest-track projection

`contains()` now requires a known footprint for a linearized track. A centerline
and `bin_size` describe the route and the lengths of its bins; they do not say
how wide the physical track is. Previously tracks without a width reported
`True` even for points far away from the track.

Pass a measured `track_width` to `Environment.linear_track`, `Environment.maze`
or `Environment.from_graph` when you need containment. It is the full width in
the coordinates' units. The footprint uses round end caps; a point must also
map to an active analysis bin, including after `subset()`.

Without a width, `contains()` raises an actionable `NotImplementedError`.
`bin_at()` still projects positions onto the nearest track bin, allowing
linearization workflows that have no measured footprint. It does not establish
physical containment in that case.

<!-- docs-test: run -->
```python
import numpy as np
from neurospatial import Environment

track = Environment.linear_track(
    endpoints=[(0.0, 0.0), (10.0, 0.0)], bin_size=2.0, track_width=2.0
)
np.testing.assert_array_equal(track.contains(np.array([[5.0, 0.5], [5.0, 1000.0]])), [True, False])
```

## Polar angular boundaries

`Environment.from_polar_egocentric(..., circular_angle=None)` now infers whether
the angular axis wraps. A full-circle range such as `(-np.pi, np.pi)` still joins
its first and last angular bins. A partial range such as
`(-np.pi / 2, np.pi / 2)` stays open, so paths and smoothing cannot jump across
the missing angles. Previously the default joined those bins for every range.

Set `circular_angle=False` to make an angular axis open explicitly, including
when you use a full circle. `circular_angle=True` now requires a full circle;
replace it with `False` or omit it when constructing a partial range. Existing
saved environments retain their stored connectivity when loaded. Rebuild
partial-range environments and recompute affected analyses to use open edges.

<!-- docs-test: run -->
```python
import numpy as np
from neurospatial import Environment

front_half = Environment.from_polar_egocentric(
    distance_range=(0.0, 10.0),
    angle_range=(-np.pi / 2, np.pi / 2),
    distance_bin_size=10.0,
    angle_bin_size=np.pi / 4,
)
assert not front_half.connectivity.has_edge(0, 3)
```

## Environment file names

Saving `env.to_file("rat1.day1")` now creates `rat1.day1.json` and
`rat1.day1.npz`. Previously it removed `.day1`, so separate sessions such as
`rat1.day1` and `rat1.day2` selected the same files. Loading uses the same
complete prefix. You can still pass either storage file name, such as
`Environment.from_file("rat1.day1.json")`.

For files written before this correction, pass their actual saved prefix:
`Environment.from_file("rat1")` reads `rat1.json` and `rat1.npz`. Loading a
missing dotted prefix does not fall back to another session's shorter name.

## Saved environments from neurospatial 0.6.0

Environment files and dictionaries now use the `Environment-v2` schema, and NWB
environment records use schema `2.0`. They store the complete binning, so
loading restores the same bins, sizes and connectivity without rebuilding the
layout. `Environment.from_file`, `Environment.from_dict` and the NWB readers
refuse `Environment-v1` files and NWB `1.x` records written by neurospatial
0.6.0 and earlier. Rebuilding them with the current factories could silently
change the bins your earlier analyses used.

To migrate, recreate each environment with the factory call and parameters you
originally used, then save it again with `env.to_file(...)` or the NWB writer.
If you no longer have that call, the `.json` half of an old file pair is plain
text. Its `layout_type` and `layout_parameters` fields record the layout and the
arguments it was built with. For example, a `MaskedGrid` record stores the
`active_mask` and `grid_edges` that `Environment.from_grid_mask` accepts:

<!-- docs-test: run -->
```python
import numpy as np
from neurospatial import Environment

# In practice: old_record = json.load(open("rat1.json"))
old_record = {
    "schema_version": "Environment-v1",
    "layout_type": "MaskedGrid",
    "layout_parameters": {
        "active_mask": [[True, True], [True, False]],
        "grid_edges": [[0.0, 2.0, 4.0], [0.0, 2.0, 4.0]],
        "connect_diagonal_neighbors": True,
    },
}
params = old_record["layout_parameters"]
env = Environment.from_grid_mask(
    np.array(params["active_mask"]),
    tuple(np.array(edges) for edges in params["grid_edges"]),
    connect_diagonal_neighbors=params["connect_diagonal_neighbors"],
)
assert env.n_bins == 3
```

Keep the old files until you have checked that the rebuilt environment's
`bin_centers` match the bins used in your earlier results.

## Smoothing rates and segmenting fields

`env.smooth(field, bandwidth=...)` defaulted to `mode="average"` in v0.6,
preserving an intensive quantity such as a rate in Hz. Later versions require
`mode=` on `smooth`, `diffuse` and `compute_kernel`: pass `mode="average"` for a
rate, `mode="transition"` to preserve a total per bin, or `mode="density"` to
convert counts to a density.

`detect_place_fields`, `has_place_field` and `population_coverage` now default
to `max_mean_rate=np.inf`: they segment maps without excluding neurons by a
rate-based cell-type assumption. An explicit finite cutoff still filters the
unweighted mean of spatial-bin rates. That mean is not total spikes divided by
recording duration. Pass `max_mean_rate=10.0` explicitly to retain the previous
map-mean filter; its output does not establish interneuron or place-cell identity.

<!-- docs-test: run -->
```python
import numpy as np
from neurospatial import Environment
from neurospatial.encoding import detect_place_fields

env = Environment.from_grid_mask(
    np.ones((4, 4), dtype=bool), grid_edges=(np.arange(5.0) * 3,) * 2
)
rate_hz = np.full(env.n_bins, 20.0)
np.testing.assert_allclose(env.smooth(rate_hz, bandwidth=3.0, mode="average"), 20.0)
fields = detect_place_fields(env, rate_hz, min_size=1)
assert fields.excluded_reason is None
# For count-to-density smoothing, use env.smooth(counts, bandwidth=3.0, mode="density").
# For the previous map-mean exclusion, pass max_mean_rate=10.0 explicitly.
```

## Mutual information and corrected metrics

`mutual_information` now takes a **joint position-response histogram**, with
positions on rows and discrete neural responses on columns. Counts or
probabilities are accepted and normalized internally. The result is bits per
observation (or nats with `base=np.e`). Choose and report the observation-window
duration and response bins; the estimate does not correct finite-sample bias.

The previous `mutual_information(firing_rate, occupancy)` call computed Skaggs
information rate in bits/second. Use `information_per_second(firing_rate,
occupancy)` to retain that calculation. Passing a rate map to the new MI function
raises an error: mean rates and occupancy alone cannot specify response
variability or the joint distribution.

<!-- docs-test: run -->
```python
from neurospatial.encoding import information_per_second, mutual_information

bits_per_second = information_per_second([0.0, 100.0], [0.5, 0.5])
bits_per_observation = mutual_information([[50, 0], [0, 50]])  # 1 bit
```

Recompute affected analyses when upgrading:

- Spatial information and sparsity now exclude bins with non-finite rates or
  occupancy and renormalize occupancy on each neuron's remaining support.
  Observed zero rates remain included.
- Spatial autocorrelation now masks missing values after centering, preserving
  a zero-lag value of one and invariance to firing-rate offsets. It uses circular
  FFT correlation with periodic boundaries and global centered-energy
  normalization, rather than per-lag Pearson correlation.
- ICA whitens PCA scores and reports each recovered component's contribution to
  reconstructed variance. Requested components beyond numerical rank have zero
  weights and activations.
- Reverse explained variance now swaps pre- and post-behavior rest periods,
  computing `r(template, control | match)²`.

## Scientific support, smoothing and missing observations

Spatial and view encoding, and smoothed object-vector maps, now choose a default
bandwidth of 5 cm in declared metric units (`0.05` in metres, `50` in millimetres).
Unspecified, pixel and custom units
use 2.5 median graph-edge lengths, falling back to bin widths for isolated bins.
Set `env.units` to describe your coordinates. To reproduce the previous literal
default, pass `bandwidth=5.0` explicitly; changing `env.units` does not rescale
your coordinates. Object-vector results inherit the supplied environment's
distance units; angular smoothing keeps its existing units and defaults.

Fitted/session decoders and functional decoders receiving a spatial rate result
now exclude unobserved or below-threshold training bins. Inspect
`rates.spatial_support` and prefer `BayesianDecoder.from_rates(rates)` or pass
`rates` directly to `decode_position`. If you pass `rates.firing_rates` instead,
also pass `prior=rates.spatial_support.astype(float)`. Zero filling alone does
not carry training support. A prior with no supported training bins raises an
actionable error.

All rate families retain `analysis_settings` through indexing, table attributes
and xarray/NetCDF. Their `spatial_support` masks follow the result's coordinates,
including angular and polar bins. Spatial results also preserve these settings
through NWB schema 2.4. Older files remain readable; unavailable settings are
`None`. CSV does not retain DataFrame attributes: save those settings separately
when using CSV.

Metadata with a `unit_id` column or a named/non-default index now aligns by unit
identity and rejects mismatched or duplicate labels. An unnamed default
`RangeIndex` without a `unit_id` column still means rows are in spike order.

Geodesic steps involving missing or outside positions now return `NaN`.
Pre-decision metrics with insufficient observations or undefined movement
headings expose `is_valid=False` and cannot suggest deliberation. Check validity
before aggregating trials; stationary tracking alone cannot measure head scanning.

For duration-weighted analysis, keep the original recording arrays and pass
`epochs=` to the analysis. `restrict()` warns when slicing aligned arrays would
lose observation boundaries. For adjacent point-event cohorts use
`in_epochs(..., closed="left")` so boundary events belong to only one cohort.
See the runnable [workflows](../user-guide/workflows.md) and
[interoperability examples](../user-guide/interoperability.md).

## Recording gaps, time windows and argument order

| Previous call | Current call |
| --- | --- |
| `Session(...)`, `load_session(...)`, `PositionLike` | NWB readers and simulation holders; pass `.times`, `.positions`, `.spike_times` and `.unit_ids` explicitly |
| `positions, times = read_position(nwbfile)` | `pos = read_position(nwbfile)`, then `pos.times`, `pos.positions` |
| `spike_trains, unit_ids = read_units(nwbfile)` | `units = read_units(nwbfile)`, then `units.spike_times`, `units.unit_ids`, `units.spike_window` |
| `session.spike_trains` (simulation) | `session.spike_times`, with integer `session.unit_ids` |
| `segment_by_velocity(positions, times, ...)` and other positions-first pairs | `segment_by_velocity(times, positions, ...)`; the changelog lists every reordered function |
| `heading_from_velocity(positions, dt)` | `heading_from_velocity(times, positions)` |
| `BayesianDecoder(env).fit(..., epoch=(t0, t1))` | `BayesianDecoder(env).fit(..., epochs=[(t0, t1)])` |
| `epochs=(starts, ends)` as two parallel arrays | `epochs=np.column_stack([starts, ends])` |
| `except IndexError` around `env.neighbors(i)` | `except BinIndexOutOfRangeError` (a `ValueError` subclass) |
| an animation export over an existing file | pass `overwrite=True` |

Analyses that combine samples over time now skip recording gaps: the default
`max_gap=0.5` (seconds) excludes any interval between samples more than half a
second apart. Tracking sampled more slowly than 2 Hz therefore has no observed
interval under the default, and the analysis warns that every interval was
excluded. Pass `max_gap=None` for intentionally coarse sampling, or a larger
value in seconds.

## Breaking change 1 — `to_xarray()` returns a `Dataset`, not a `DataArray`

`to_xarray()` previously returned an `xarray.DataArray` indexed by integer
`neuron`. It now returns a labeled **`xarray.Dataset`** whose `unit_id`
coordinate holds your *real* per-unit identity labels (`result.unit_ids`), so
units are selected by **label**, not position.

```python
# BEFORE — DataArray with integer "neuron" coords
da = result.to_xarray()
firing = da.sel(neuron=0)        # select the first neuron by integer position
values = da.values               # raw rate matrix

# AFTER — Dataset with real unit_id labels
ds = result.to_xarray()
firing = ds.sel(unit_id=result.unit_ids[0])   # select by label
values = ds["firing_rate"].values              # rate matrix lives in a data var
```

Key points:

- **Population rate results** (`SpatialRatesResult`, `DirectionalRatesResult`,
  `ViewRatesResult`, `ObjectVectorRatesResult`) → dims `("unit_id", "bin")`. The
  rate matrix is the `firing_rate` data var; `occupancy` is a `("bin",)` data
  var. The `bin` dimension carries non-index `bin_center_x` / `bin_center_y`
  (/`bin_center_z`) coordinates (or `bin_center_distance` / `bin_center_angle`
  for the polar egocentric result).
- **Decode results** (`DecodingResult`) → dims `("time", "bin")` — a posterior
  over space per time bin, with **no `unit_id` axis**. The posterior lives in
  the `posterior` data var.
- **Duplicate `unit_ids` now raise `ValueError`** — label-based selection
  requires unique labels.
- `to_xarray()` requires the optional `xarray` extra:
  `uv pip install "neurospatial[xarray]"` (or `uv add xarray`).

## Breaking change 2 — batch `to_dataframe()` is dense; the summary moved to `summary_table()`

On the **batch (plural) encoding results** — `SpatialRatesResult`,
`DirectionalRatesResult`, `ViewRatesResult`, `ObjectVectorRatesResult` —
`to_dataframe()` used to return a **per-unit summary** (one row per neuron, with
`peak_x`, `peak_rate`, `spatial_info`, `cell_type`, …). That summary has moved
to the new **`summary_table()`**. `to_dataframe()` is now **dense tidy**: one
row per `(unit, bin)`, always carrying a `unit_id` column.

```python
# BEFORE — to_dataframe() was the per-unit summary
df = result.to_dataframe()              # one row per neuron: neuron_id, peak_x, ...
place = df[df["cell_type"] == "place"]

# AFTER — summary_table() is the per-unit summary; to_dataframe() is dense
summary = result.summary_table()        # one row per unit, unit_id-indexed
place = summary[summary["cell_type"] == "place"]

dense = result.to_dataframe()           # one row per (unit, bin), carries unit_id
```

The old `neuron_ids=` keyword on the per-unit `to_dataframe()` is replaced by
`unit_ids=` on `summary_table()` (defaulting to the result's own `unit_ids`).

## Breaking change 3 — object-vector reference frames and result names

Object-vector results use `ObjectVectorRateResult` / `ObjectVectorRatesResult`
and `spatial_information()`, in both frames, without old-name aliases.
`direction_frame` is required when constructing results directly and preserved
when indexing a population. `compute_object_vector_rate(s)` uses world-frame
direction and takes no headings; `compute_egocentric_rate(s)` retains required
headings for animal-relative bearing.

For existing heading-relative free predicates, use
`is_egocentric_object_vector_cell(env, spikes, times, positions, headings, objects)`.
The free `is_object_vector_cell(env, spikes, times, positions, objects)` now
uses allocentric direction. Result predicate methods use their recorded frame.
`ObjectVectorCellModel` defaults to allocentric tuning; configure
`direction_frame="egocentric"` to preserve heading-relative simulation.
Both frames measure animal-to-object direction, so the reverse vector adds pi.

## Cell predicate migration

The old `is_place_cell()` field detector is now `has_place_field()` (free
function and method), with the same detector defaults. New `is_place_cell()`
requires `criterion="spatial_info"` or `"shuffle"`; its result method requires
`criterion="spatial_info"`. Other free cell predicates keep threshold screens
by default and add `criterion="shuffle"` with raw arrays. Wrong-mode keywords
raise, and invalid raw inputs propagate errors instead of returning `False`.

All method thresholds are keyword-only; `None` resolves the family defaults.
Information/MVL cutoffs use `>=`; p-value levels use `<`. Spatial batch
`classify(min_spatial_info=...)` is now `classify(min_info=...)`.
Result methods and batch classifiers keep no raw arrays and cannot shuffle.
Use the five `*_cell_significance` functions for population significance.

The following detector aliases have been removed:

| Removed | Replacement |
| --- | --- |
| `ObjectVectorRatesResult.detect_ovcs(...)` | `ObjectVectorRatesResult.classify(...)` |
| `ViewRatesResult.detect_view_cells(...)` | `ViewRatesResult.classify(...)` |
| `DirectionalRatesResult.detect_hd_cells(...)` | `DirectionalRatesResult.classify(...)` |
| `SpatialRatesResult.detect_cell_types(...)` | `SpatialRatesResult.label_cell_types(...)` |

## Removed view peak aliases

Use the shared peak accessors; the old methods have been deleted.

| Removed | Replacement |
| --- | --- |
| `ViewRateResult.peak_view_location()` | `ViewRateResult.peak_location()` |
| `ViewRatesResult.peak_view_location()` | `ViewRatesResult.peak_locations()` |

Notes:

- **`classify` vs `label_cell_types` are deliberately separate.** `classify()`
  is a single-type **boolean** predicate (`NDArray[bool]`);
  `label_cell_types()` is the multi-class **string** labeler
  (`"place"`/`"grid"`/`"border"`/`"unclassified"`). They are not merged because
  collapsing a bool predicate and a str labeler under one name would silently
  change a return type and break `df[col == "place"]` filters.
- **`detect_region_crossings` argument order** moved `env` to slot 3 to match
  the behavioral-segmentation convention. The old positional order has been removed; pass `region_name=` as a
  keyword.

## Namespace and root workflow imports

The root now exposes the four-array spatial encoding path, its result types,
position decoding/results and peri-event histograms/results through lazy,
statically typed imports. Specialized APIs live in their owning domains:

| Previous import or call | Current API |
| --- | --- |
| `neurospatial.BayesianDecoder` | `neurospatial.decoding.BayesianDecoder` |
| `neurospatial.bin_spikes_in_time` | `neurospatial.decoding.bin_spikes_in_time` |
| `neurospatial.SpikeTrains` | `neurospatial.encoding.SpikeTrains` |
| `neurospatial.restrict` | `neurospatial.behavior.restrict` |
| `encoding.phase_precession(...)` | `encoding.compute_phase_precession(...)` |
| `decoding.poisson_likelihood(...)` | `log_poisson_likelihood(...)` followed by `normalize_to_posterior(...)` |
| `behavior.integrated_absolute_rotation(...)` | `behavior.head_sweep_magnitude(...)` |
| `ops.Affine3D` | `ops.AffineND` |
| `animation.SpikeOverlay` | `animation.EventOverlay` |
| `ImageMaskLayout.build(bin_size=...)` | `ImageMaskLayout.build(pixel_size=...)` |
| Surrogate generators from `stats.shuffle` | `stats.surrogates` or `stats` |
| `animation.VideoCalibration` | `ops.VideoCalibration` |
| `ops.heading_from_velocity`, `ops.heading_from_body_orientation` | `behavior.heading_from_velocity`, `behavior.heading_from_body_orientation` |
| `events.distance_to_reward`, `events.distance_to_boundary` | `behavior.distance_to_reward`, `behavior.distance_to_boundary` |

Normalizer functions, event validators, animation data/protocol types and
renderer/cache helpers leave the public domain-root imports. Pass the raw
arrays to the documented workflows and use built-in overlay types.

## Runnable migration snippet

The population export workflow, end to end:

<!-- docs-test: run -->
```python
import numpy as np

from neurospatial import Environment
from neurospatial.encoding import compute_spatial_rates

# --- tiny simulated session: 3 units on a small open arena ---
rng = np.random.default_rng(0)
t = np.linspace(0.0, 30.0, 600)
positions = np.column_stack(
    [
        50.0 + 30.0 * np.cos(2 * np.pi * t / 30.0),
        50.0 + 30.0 * np.sin(2 * np.pi * t / 30.0),
    ]
)
times = t
env = Environment.from_samples(positions, bin_size=5.0)

# Three units, each with a different (sparse) spike train.
spike_times = [times[::5], times[::7], times[::9]]
unit_ids = np.array(["u1", "u2", "u3"])

result = compute_spatial_rates(
    env, spike_times, times, positions, unit_ids=unit_ids
)

# --- Break 2a: summary_table() is the per-unit summary (one row per unit) ---
summary = result.summary_table()
assert len(summary) == 3  # one row per unit
assert "u2" in summary.index  # unit_id-indexed

# --- Break 2b: to_dataframe() is now dense (one row per (unit, bin)) ---
dense = result.to_dataframe()
assert "unit_id" in dense.columns
assert len(dense) == 3 * env.n_bins  # one row per (unit, bin)

# --- Break 1: to_xarray() is a labeled Dataset selected by unit_id label ---
# Requires the optional `xarray` extra; demonstrated skip-safe so this snippet
# runs on the default (no-xarray) install too.
try:
    ds = result.to_xarray()
except ImportError:
    print("xarray not installed; skipping to_xarray() demo")
else:
    assert set(ds.dims) >= {"unit_id", "bin"}
    firing = ds.sel(unit_id="u2")["firing_rate"]  # select by label, not position
    assert firing.shape == (env.n_bins,)
    print("to_xarray() Dataset OK:", dict(ds.dims))

print("migration snippet OK")
```
